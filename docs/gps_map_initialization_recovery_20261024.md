# GPS 지도 초기화 실패 후 복구

지도 상태 요청이 한 번 실패하면 기존 코드는 rejected Promise 또는 `ok:false` 응답을 영구 캐시했다. 이후 새 GPS 표본이나 기록 재생이 지도 초기화를 다시 시도해도 같은 실패를 받았다. HTTP 오류 본문이 `ok:true`라면 HTTP 상태를 무시하고 초기화를 진행하기도 했다.

이 후보는 성공한 상태 응답과 진행 중 요청은 계속 공유하고, 실패한 응답만 캐시에서 제거한다. 각 지도는 초기화 실패 후 2초 동안 재시도를 제한한다. 덕분에 빠른 기록 재생 표본이 실패한 네트워크·폰트·스타일 로드를 연속 실행하지 않으며, 이후 표본이나 페이지 재진입에서 복구할 수 있다. 별도 자동 타이머나 새 구독은 만들지 않는다.

GPS 좌표·시간 선택·경로·사용자가 해제한 위치 추적 상태, 수동 조종·STOP·임대·소유권·기록 재생 시계는 바꾸지 않는다. 네트워크 요청 자체가 종료되지 않는 문제는 이번 수정 범위가 아니다.

`tests/test_gps_init_recovery.mjs`는 제품의 실제 bundle/init/create를 추출해 HTTP 503·네트워크 거부·JSON 오류·지도 미준비·스타일 실패·동시 초기화·수동 이동 상태를 생성 응답으로 검증한다. 실제 브라우저·느린 회선·Jetson 배포 검증은 별도로 수행해야 한다. 기존 GPS paint 시험의 fetch/performance stub도 실제 브라우저 계약에 맞췄다.
