# 10월 8일 과수원 시험 준비: 검증 결과와 남은 조건

현재 차량은 휠 엔코더가 없다. 위치 추정에는 원시 2D LiDAR, native IMU,
품질 조건을 통과한 GNSS만 사용한다. PWM은 명령 기록이며 바퀴 속도나
이동 거리 측정값이 아니다. 카메라는 표시·녹화에 사용하고 매핑에는 사용하지 않는다.

## 10월 3일 기록을 먼저 확인한 결과

전체 7개 기록, 총 32,047개 LaserScan을 다시 읽고 추출 파일 SHA-256을
manifest와 비교했다. 현재 Jetson의 연속 위치 추정 코드 두 파일도 로컬 코드와
해시가 일치했다. 기존 전체 평가·ARM 재생 검증을 다시 확인했으며, 중간에
새 좌표계로 바꾸지 않는 경로가 유지된다. 이번에 동일한 전체 정합을 중복 실행하지 않았다.

지도에 그리지 않은 관측에는 정합 거부와 짧은 GNSS·IMU 이동 추정이 있다.
불확실한 이동 추정으로 광선을 그려 미관측 영역을 자유 공간으로 만들지 않는다.
기존 정합 계산 p95는 기록별 약 134–199ms다. 자체 정합·gyro 일치와 실제
지형 정확도는 서로 다른 검증이다. 장거리 형상 오차는 해결 완료로 표시하지 않는다.

GPS의 보고 수평 정확도는 약 3–10m였다. F9P의 RTK 사양을 이 기록에서
실제로 달성한 정확도로 적용하지 않는다. IMU의 충격·축 방향 변화가 관측된다.
IMU 센서 +Z와 중력 수직의 각도는 **차체 기울기의 교정된 측정값이 아니다**.
LiDAR–IMU 회전·LiDAR의 차체 기준 위치를 따로 확인해야 한다.

## 9월 10일 과수원 기록

7개 MCAP을 Jetson에서 원본 변경 없이 전부 추출하고 전체 센서 통계를 검사했다.
총 LiDAR 15,566스캔, 원시 IMU 30,617개다. GPS 토픽은 없으며 카메라
표본은 1280×720이고 상당히 어둡다. 1초 간격 LiDAR 표본으로 과수열 후보를
검사하고 원시 점 그림을 직접 확인했다. 전체 센서 검사와 1초 간격 인식 평가는 구분한다.

IMU 센서 +Z의 수직 방향 대비 중앙값은 기록별 약 76–89도다. 이전 장착 방향이
현재와 다르다는 근거이며 차체가 그 각도로 기울었다는 주장이 아니다. 당시
`imu_calibration.json`은 참고용으로 보존하고 현 차량 설정에 적용하지 않는다.
이전 차체의 레버 암·스캔 평면·진동 조건으로 현재 차량의 제동/속도를 교정하지 않는다.

기존 전방 ±35도·전체 30m 후보 검색에서는 모든 표본의 과수열 후보가 거부됐다.
많은 반사·가지와 미확인 LiDAR 방향 때문에 단순한 기둥 후보에만 의존할 수 없다.
10m 지지점 범위와 넓은 센서 좌표계 방향 검색을 별도 오프라인 후보로 시험했으나,
이것도 실제 주행에 쓸 검증된 과수열 추정이 아니다. 반사를 후보에서 제외해도
원시 장애물/충돌 검사에서 지우거나 자유 공간으로 취급하지 않는다.

실제 드라이버 스캔은 두 날짜 모두 3,240점이다. 명목 3,200점 상한 때문에
모든 실차 패킷을 거부하던 오프라인 인식 후보를 4,096점 한도로 수정했다.
조합 계산과 모호성 거부 한도는 유지한다. 안정된 가지도 기둥이라고 단정하지 않는다.

## 실제 대시보드 준비 점검

`GET /api/autonomy/preflight`는 설정과 현재 지도 상태를 읽고 미완료 조건을
반환한다. 설정은 `config/field_autonomy_preparation.json`이다. 속도 선호는
기존 `/api/autonomy/speed`에 유지한다. 제안 목표 0.15m/s·0.15rad/s는 시험
준비값이고 측정된 차량 성능/안전 속도가 아니다. 제자리 회전은 준비 설정에서 꺼져 있다.

원본 자료 검토는 완료로 표시하지만 다음은 미완료다: 현재 차체 치수 실측,
센서 외부 파라미터·평면 유효 범위, 몸체 선속도/각속도 피드백과 PWM 응답,
물리 비상정지, 해당 속도/하중의 정지거리·정지시간, 실제 주행 위치 정확도,
실시간 지연·장애물/미관측 정지·회전 공간·수동 인계·작업 경계 검증.

점검 파일을 모두 채워도 이 경로는 모터 출력 권한을 발행하지 않는다.
`/api/autonomy/start`는 계속 거부된다. 모터를 자동 구동하는 runtime 연결은
이번 설정/자료 검토와 별도의 미완료 구현·검증 단계다.

## 현장 시험 순서

1. 모터 전원을 즉시 차단할 장치와 수동 STOP/통신 상실 정지를 확인한다.
2. 현재 차체·LiDAR의 차체 기준 x/y/yaw·IMU의 LiDAR 기준 회전을 측정한다.
   화면의 180도 회전 보정은 센서 외부 파라미터 교정이 아니다.
3. 먼저 정지 상태와 짧은 **수동** 직진/회전에서 원시 센서와 PWM을 녹화한다.
   실제 움직임·LiDAR 정합·중력 투영 gyro·시간 지연을 비교한다.
4. 시험 속도/하중에서 STOP부터 실제 정지까지의 거리·시간·진동을 측정한다.
   바퀴가 완전히 평행하지 않은 직진 편향과 좌우 PWM 차이의 실제 반응을 확인한다.
5. 장애물/미관측/열 중간 빈틈/열 너머 벽/막힌 회전 공간에서 **관찰 판단**을 검증한다.
   과거 자유 셀을 최신 충돌 검사로 쓰지 않는다. 마지막 열은 작업 경계와 관측
   범위가 확인되기 전까지 `UNKNOWN`으로 유지한다.
6. 위 자료로 현재 차량의 피드백·감속 한계를 교정하고 출력 없는 판단 시험을 통과한
   후, 별도로 제한된 실차 자동 제어를 연결·검증한다.

ROS 좌표는 [REP-103](https://github.com/ros-infrastructure/rep/blob/master/rep-0103.rst)의
차체 x 전방/y 왼쪽/z 위쪽 규약과 측정한 센서 변환으로 맞춘다.
[LaserScan 정의](https://github.com/ros2/common_interfaces/blob/rolling/sensor_msgs/msg/LaserScan.msg)의
header·빔 간 시각 의미를 확인했으나, S2 드라이버의 보간·복제·배열 반전 때문에
기존 기록에 `time_increment`만으로 빔 취득 순서를 단정해 deskew를 적용하지 않는다.

정밀 좌표·원본 센서·영상·개별 궤적은 private audit에 보관한다. GitHub Actions를
사용하지 않고 로컬/Jetson 후보 검증 후 SSH로 web 역할만 적용한다.
