# 녹화된 모터 핀 신호

이 기능 적용 후 시작한 카메라·LiDAR·동시 녹화는 모터 상태도 저장합니다. IMU/GPS 저장 여부와 무관하며, 기록을 위해 모터를 구동하거나 조종 권한을 얻지 않습니다. 기존 녹화에는 누락된 신호를 만들어 넣지 않습니다.

## 실제 Jetson 적용 상태

2026-09-29 KST에 `8fe7cd6ef37aa1d5fef8bc4b4f582d7e21b80c33`을 적용했습니다. 대시보드와 녹화기 두 서비스만 교체했으며, 나머지 14개 컨테이너·기존 32개 녹화·설정·기존 Compose 파일은 유지했습니다. 배포 검사 36개가 통과했고, 녹화하지 않은 상태에서도 모터 상태 수신·1.5초 이내 갱신·오류 없음·기록 표본 0개를 확인했습니다.

Jetson ARM Iron 후보 이미지의 격리 검사 24개(9.243초), 로컬 Iron 전체 검사 144개(36.028초, 건너뜀 없음), 녹화 재생 JavaScript 검사와 [GitHub CI](https://github.com/2026-BTS-UNI-Car/unist_orachard_dashboard/actions/runs/36564999759)가 통과했습니다. 실제 새 녹화나 차량 구동은 수행하지 않았습니다. 현재 브라우저 접속은 `ERR_PROXY_CONNECTION_FAILED`로 실패했으므로, 이 버전의 실제 화면 확인까지 통과한 상태는 아닙니다. [배포 검증 자료](jetson_motor_recording_validation.json)와 [복구 체크포인트](../RAW_DEPLOYMENT.md)를 참고하세요.

## 저장과 재생

- ROS bag: `/rover/status`, `/rover/control/requested`, `/rover/control/applied`를 함께 기록합니다.
- `motor.jsonl`: `/rover/status`로 받은 핀별 상태를 전체 기간 저장합니다. 현재 실제 bridge의 발행 주기는 약 2Hz입니다.
- `timeline.json`: `orchard.motor_pwm.timeline.v1` 메타데이터와 최대 1,800개 미리보기 표본을 보관합니다. 이전 구간을 탐색하면 JSONL에서 읽습니다.
- 녹화 재생 화면의 IMU 아래 표는 현재 재생 시각 이전의 마지막 표본을 표시합니다. 이후 시각의 신호를 미리 보여주지 않습니다.

| 역할 | NodeMCU 핀 | ESP GPIO |
| --- | --- | --- |
| 왼쪽 정방향 / 역방향 | D8 / D5 | 15 / 14 |
| 오른쪽 정방향 / 역방향 | D3 / D0 | 0 / 16 |
| 드라이버 활성화 | D1 / D2 / D6 / D7 | 5 / 4 / 12 / 13 |

핀 매핑은 현재 `esp_wheel_controller.py`와 대조하는 회귀 검사로 유지합니다. 기록 파일에도 당시 매핑을 저장하므로, 나중의 설정을 과거 기록에 적용하지 않습니다.

## 값의 의미와 한계

**요청 PWM**은 좌우 signed percent 요청에서 계산한 0–255 값입니다. 예를 들어 +50%는 정방향128·역방향0입니다. 실제 직렬 전송 로그나 MCU 목표값은 아닙니다. **MCU 보고 PWM**은 ESP에서 마지막으로 받은 핀 출력 캐시입니다. 두 값은 가감속 중 다를 수 있습니다. 표시하는 백분율은 PWM/255이며, 바퀴 속도나 공급 전압 측정값이 아닙니다.

실제 차량에는 휠 엔코더가 없습니다. 이 기록은 모터에 요청하거나 MCU가 보고한 신호의 기록이며, 주행 거리·실측 속도·엔코더 기반 odometry로 사용할 수 없습니다.

연결이 끊겨도 마지막 보고값을 0으로 바꾸지 않습니다. 미제공 값은 미기록으로 표시합니다. 조종 해제 시에도 현재 펌웨어의 활성화 핀 D1/D2/D6/D7은255를 보고할 수 있습니다. 이 핀을 방향 핀과 동일하게 해석하지 않습니다.

상태 파일의 시각, 수집 시각, 오래된 표본 여부를 함께 기록합니다. 핀별 MCU 보고 시각·PWM 주파수·전압·모든 직렬 명령/출력 변화·실측 바퀴 속도는 제공되지 않습니다. 짧은 출력 변화는 2Hz 표본 사이에서 누락될 수 있습니다.

센서와 모터의 재생 시각은 기존 녹화의 호스트 wall-clock 경과 시간을 공유합니다. 모터 표본은 독립적인 monotonic 경과 시간과 시계 차이도 남깁니다. 시스템 시각이 뒤로 바뀌어 순서를 역전시키는 표본은 진단과 함께 제외합니다. 이 변경이 기존 센서의 시계 보정 문제 전체를 해결한 것은 아닙니다.

전체 신호는 JSONL에 남기고 메모리의 미리보기만 제한합니다. 파일 쓰기/읽기 실패나 일부 손상은 표시하며, 기존 센서 기록을 중단하거나 핀 값을 추정해 채우지 않습니다.

## 시뮬레이션 복제본

`simulated: true` 또는 SIM 펌웨어 식별자가 있는 상태는 별도로 분류합니다. SIM의 약4Hz 상태에 포함된 출력은 가감속 모델의 적용 속도 명령을 0–255로 환산한 값이며, MCU 수신값이나 물리 엔진에서 측정한 바퀴 속도가 아닙니다. `simulated_output_pwm`에 저장하고 `reported_pwm`은 비워 둡니다. 재생 표에도 **시뮬레이션 출력 PWM**으로 표시합니다. SIM에서 제공하지 않는 활성화 핀 출력은 미기록 상태를 유지합니다.
