# 지도 재생·누적·이어가기 개선 상태

Jetson에 `570cfaf` 소스를 직접 SSH로 배포했다. 기존 카메라·LiDAR·IMU·GPS·모터
서비스의 소유권과 설정, 원본 기록, 저장된 live 지도는 배포 검증에서 유지됐다.
ARM 55개 검사와 로컬 웹 지도 11종 검사를 통과했다. GitHub Actions를 사용하지 않았다.

## 재생 시각에 맞는 지도

지도 영상 대신 압축된 격자 셀 변경분과 좌표·경로를 전송하고 브라우저가 그린다.
이미 계산한 구간은 시각별 셀 창을 미리 내려받는다. 캐시 경계는 2초를 겹쳐
받아 이전 지도에서 이어 그리며, 동일한 셀 타일은 기존 bitmap을 재사용한다.
새 지도는 원시 센서를 재생 시각까지만 계산한다. 미래의 지도 셀을 먼저 표시하지 않는다.

지도 데이터가 준비되지 않으면 영상·센서의 공통 재생 시각도 버퍼링한다.
지도만 몇 초 뒤에서 따라오는 상황을 줄였으며, 부족한 대역폭에서 멈춤이
전혀 없다는 보장은 아니다. 사용자 일시정지는 늦은 Play/영상 재개 응답보다
우선한다. 정지 확인 뒤 추가 스캔을 지도에 누적하지 않는다.

중간에 빈 seed가 반복해서 지도를 지우던 문제를 수정했다. 지도 크기 증가와
같은 epoch의 되감기에서도 사용자가 선택한 중심·확대 배율을 유지한다.
되감기는 해당 시각 이후의 관측을 숨기고, 다시 재생하면 같은 누적 기록을 표시한다.

## 서버 재시작 뒤 이어가기

기록 전용 체크포인트에 기준 LiDAR 스캔·누적 원본 gyro·GPS 제약·원시 gzip
행 위치·손실 없는 signed 격자 셀을 함께 저장한다. 원본 해시, 지도 epoch,
측위/격자 코드 fingerprint, NumPy/SciPy 버전이 일치할 때만 복원한다.
현재 차량의 물리적인 위치를 이 파일에서 복원하지 않는다.

기본 저장 간격은 기록 시각 2초이며 최근 2개 이어가기 묶음을 유지한다.
최신 묶음이 손상되면 이전 검증 가능한 묶음을 사용한다. 모두 사용할 수
없으면 원본 센서로 복구하며, 체크포인트 저장 오류가 지도 생성을 중단하지 않는다.
기록 원본·시각별 지도 이벤트·기존 지도 epoch는 이 정리 대상에 포함하지 않는다.

080909 기록의 2,093개 원시 스캔 전체 시험에서 재시작 전후 signed 셀·좌표·경로가
중단 없이 계산한 참조와 동일했다. 110초 부근에서 재시작한 뒤 첫 새 스캔까지
약 3.90초였다. 재계산할 짧은 꼬리, gzip seek, 프로세스 시작 시간이 포함된다.
2초 저장 후보의 앞부분/뒷부분 시험은 약 91.19/109.06초였고, 이어가기 묶음은
2개로 유지됐다. 장치 부하와 기록 규모에 따라 시간은 달라진다.

## 상대 성능 측정과 정확도 범위

072530의 이미 계산한 동일 20–80초 구간을 HTTP 512kbps/250ms, 고정 360p 영상으로
비교했다. 셀 commit 순간 지도와 재생 시각의 차이 p95는 기존 프로토콜 약
1.49초에서 공통 시각 버퍼링 후보 약 0.094초로 줄었다. 표시 commit은 기록
1초당 약 3.18회에서 7.70회로 늘었다. 이 수치는 네트워크 왕복 지연이 아니다.
공통 시각 후보에도 해당 구간에서 약 5.6초의 버퍼링 표본이 있었고, 일반
프레임 표본의 시각 차이 p95는 약 0.227초였다. WebSocket까지 같은 제한을
받았다는 근거로 사용하지 않는다. 마지막 타일 재사용·경계 겹침 버전의
브라우저 검증 결과는 UBTS TODO 체크포인트에서 구분한다.

최종 배포본의 별도 83초 재생 시험에서는 첫 초기화 이후 타일 reset이
0회였고, 일시정지 뒤 약 128초간 revision이 유지됐다. 수동 중심·배율은
되감기 뒤에도 동일했다. 해당 시험의 20–80초 commit 시각 차이 p95는
약 0.113초, 타일 적용 시간 p95는 약 22.25ms였다. 고정 360p 영상의
버퍼링 때문에 기록 시각 60초에 약 172.71초의 wall time이 걸렸다.
따라서 이를 영상까지 1배속 실시간 재생을 보장한 결과로 해석하지 않는다.
평상시에는 영상 화질 자동 선택이 가용 대역폭에 맞는 variant를 선택한다.

실시간 지도도 기록 재생과 같은 원시 LiDAR·native IMU·품질 GNSS의 고정
좌표계 측위를 사용한다. source-only 전체 시험은 별도 격리 환경에서
실행했다. 080909의 live 경로 시험은 약 204.91초에 210.12초 기록을 처리했다.
실제 움직이는 차체에서 독립 측량에 의한 위치 정확도를 검증한 결과는 아니다.

정지 편향과 실제 회전 보존, 보수적인 free-ray 감쇠와 endpoint guard는
[앞선 정확도 변경](MAP_SPEED_ACCURACY_20261005.md)에 설명한다. 전송·이어가기
변경은 그 측위 수학을 바꾸지 않는다. gyro bias 후보는 세 전체 기록에서
개선이 작거나 혼재되어 채택하지 않았다. 멀리 있는 점을 숨기거나 원본 IMU를
변경해 지도 정확도가 좋아졌다고 판단하지 않는다.

원거리 장기 정합, 실제 LiDAR–IMU 기울기, 개별 빔의 획득 순서와 시각,
전역 drift는 추가 검증이 필요하다. 휠 엔코더가 없으며 PWM은 실제 속도나
이동량으로 사용하지 않는다. 카메라는 표시·기록용이고 현재 측위 입력이 아니다.
실차 자율 모터 출력은 제동/측위 검증 전까지 계속 보류한다. SIM mapper의
공통 경로 이식은 별도 미완료 항목이며 실제 배포 완료로 표시하지 않는다.

원시 위치·영상·개별 센서/핀 로그·브라우저 캡처는 public repository에 넣지 않는다.
배포·원본 비교·브라우저 계측의 상세 근거는 UBTS의 private audit 폴더와
`todo.md`, 시뮬레이션 저장소 `docs/UBTS_TODO.md`에 체크포인트로 남긴다.
