# 기록 지도 보존 및 센서 화면 개선 · 2026-10-04

GPS 재생마다 지도 resize를 호출하던 동작을 제거했다. Pointer 입력을 MapLibre보다 먼저 받아 중심 추적을 해제하므로 새 위치 표본이 드래그 시작을 취소하지 않는다. 중심 버튼으로 추적을 다시 켤 수 있다.

전체 센서 모드의 지도 칸 240px / Canvas 420px 불일치와 IMU 최소 높이를 수정했다. 센서 패널은 컨테이너 폭에 따라 배치하고 지도 도구줄을 Canvas 밖에 둔다. `로버 주변`은 가까운 관측 물체와 로버에 자동 맞추고, `구간 전체`는 현재 좌표계의 전체 지도에 맞춘다. 수동 확대와 드래그는 자동 맞춤을 해제한다.

위치 추정 공백 뒤의 지도들은 서로 다른 local origin을 가진다. 원시 자료와 이전 native grid는 삭제되지 않았으나 화면은 현재 구간만 보여주고 있었다. 재생 시각까지 관측한 구간 목록과 이전 화면 미리보기를 유지하고 구간 선택 시 카메라·LiDAR·IMU·GPS·PWM을 해당 시점으로 함께 탐색한다. 역방향 탐색에는 미래 구간이나 미래 미리보기를 표시하지 않는다. 구간 목록은 원시 history를 변경하지 않는 읽기 전용 index다.

10월 3일 7개 기록의 모든 finite 반사점과 관측 광선을 사용한 raster 재생성을 마쳤다. 30,742개 승인 스캔 / 98개 분리 구간이다. 저장된 이전 epoch·원시 bag·metadata·GPS·PWM은 보존했다. 광선의 빈 공간도 전부 계산하며 SIMD/NumPy endpoint 변환과 bounded bitmap Bresenham 계산을 사용한다. 두 과수원 각 100개 스캔에서 endpoint 보존율은 100%, Windows raster p95는 약 45/51ms였다. 절대 지형 정확도를 측정한 수치는 아니다.

과수원에서는 미지원/불일치 정합 475/270회, 도로에서는 진동 gate와 일부 정합 실패가 주요 중단 원인이다. 현 알고리즘에 사전 과수열 모델이나 바퀴 엔코더 입력은 없다. PWM을 실제 이동거리로 변환하지 않는다. 카메라는 표시와 기록에 사용하며 매핑에는 넣지 않았다.

다음 위치 추정 개선은 scan-to-submap과 검증된 재위치 추정, 단절 구간 제약과 pose graph를 분리한다. IMU 장착 회전/beam 시간 순서/센서 평면 변화와 GNSS 정확도·lever arm을 먼저 검증한다. 새 나무 배열이나 도로에서도 같은 관측 가능성·모호성·잔차 gate를 적용하고, 반복되는 나무를 잘못 연결하는 후보는 거부한다. 모든 기록의 비교쌍, 새로 연결한 공백의 양방향 정합, 장기 drift, 지연을 함께 검증한 후보만 기존 지도와 교체한다. 기존 signed gyro·recent submap·pose graph 후보는 기록 간 일관된 개선을 입증하지 못해 배포하지 않았다.

이 방향은 [Cartographer의 local submap / global constraint 분리](https://google-cartographer-ros.readthedocs.io/en/latest/algo_walkthrough.html)를 참고한다. 해당 라이브러리로 교체하거나 원시 scan을 live ROS로 재생한 것은 아니다. 현재 연속 지도의 절대 정확도와 실차 자율 모터 출력은 검증되지 않았다.

설치 image/commit, ARM 검사, 브라우저 및 SIM 검증 결과는 UBTS TODO와 private `integrated-runtime-checkpoint.json`에서 확인한다. 원시 좌표·영상·궤적은 public Git에 포함하지 않는다.
