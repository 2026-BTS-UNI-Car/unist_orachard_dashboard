# USB GPS 재연결 처리

2026-09-30에 PC 분석 후 GPS를 Jetson으로 되돌렸을 때 드라이버가 종료된 상태를
확인했습니다. USB 분리로 발생한 I/O 오류를 정리하던 `termios.tcsetattr()`에서
`termios.error`가 발생했고, 기존 `OSError` 처리로 잡히지 않아 프로세스가 종료됐습니다.
그때 장치가 없어 Docker 재시작도 실패했습니다. GPS가 돌아온 후 같은 기존 컨테이너를
시작해 새 패킷 진행을 확인했습니다. 다른 15개 컨테이너·기존 32개 기록·설정은 보존했습니다.

수정한 드라이버는 termios 복구 실패와 별개로 직렬 fd·독점 모드·파일 잠금을 정리합니다.
분리 시 기존 fix를 즉시 무효화하고 5초 간격으로 같은 설정 경로를 다시 엽니다.
수동 수신 모드도 hangup을 감지하며, 재연결에서는 이전 부분 패킷·수신기 식별·위치와
카운터를 초기화합니다. 새 정상 패킷을 받기 전에는 이전 오류를 성공으로 바꾸지 않습니다.
수신기 설정·출력 주기·리셋·Flash 쓰기는 추가하지 않았습니다.

로컬 ROS Iron Linux 격리 컨테이너에서 기존 GPS 13개와 신규 재연결 8개, 총 21개 검사가
통과했습니다. 실제 PTY 분리/같은 경로 재연결, 포트 정리 실패 후 fd/잠금 해제,
중복 close, 없는 장치 재시도, 이전 위치 무효화와 ROS 종료를 검사했습니다.
Jetson ARM에서도 21개 검사를 모두 통과한 뒤 GPS driver 한 서비스에 직접 SSH로 적용했습니다.
배포 후 10개 검사를 통과했고, API 6표본에서 정상 패킷609→769·거절0·연결 유지·위치 미확정을 확인했습니다.
다른15개 컨테이너와 기존32개 기록의 메타데이터·설정은 유지했습니다.
[배포 검증](jetson_gps_reconnect_deployment.json)에 첫 ARM 검사 실패와 해결도 함께 남겼습니다.

이 수정은 드라이버의 분리 처리와 같은 장치 경로의 복구를 다룹니다. Docker의 정적
`devices` 매핑은 그대로이므로 장치가 없는 상태에서 컨테이너 최초 시작,
다른 `ttyACM` minor 번호로 재등장하는 경우까지 해결됐다고 간주하지 않습니다.
실제 USB를 다시 뽑아 수행하는 수정 후 현장 재연결 검증도 아직 하지 않았습니다.
