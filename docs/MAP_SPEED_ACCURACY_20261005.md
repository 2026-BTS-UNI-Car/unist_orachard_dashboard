# 기록 지도 처리와 관측 유지 개선

이번 변경은 기록 재생 지도에 적용한다. 휠 엔코더나 PWM을 실제 이동량으로
간주하지 않고, 원시 GPS·IMU·LiDAR 관측을 기록된 순서대로 처리한다.

일시정지 요청이 서버에서 확인되면 다음 지도 관측을 누적하지 않는다. 이미
요청된 많은 스캔이 남아 있어도 정지 상태에서 따라잡기를 계속하지 않는다.
각 브라우저의 제어 요청에 순서를 붙여 지연 도착한 이전 Play가 Pause를
취소하지 못하게 했다. 재개하면 처리하지 않은 원본 관측부터 이어간다.
브라우저는 정지 중에 미처리 작업을 확인하는 반복 조회도 중단한다. 현재
진행 중인 한 번의 격자 갱신과 HTTP 응답에 필요한 시간은 남을 수 있다.

거리 단위의 정합 잔차와 IMU 각도 prior가 같은 최소제곱 문제에서 과도하게
비교되던 가중치를 수정했다. 정지한 채 5초가 지나도 유효한 고정 참조를
계속 사용한다. 좋은 관측에서 중복 정합을 반복하지 않으며, 약한 관측의
넓은 탐색과 복구는 유지한다. 편향된 gyro를 포함한 정지 테스트와 실제
회전을 보존하는 테스트를 함께 통과했다.

반복 관측된 장애물 셀은 빈 공간 관측 한두 번으로 빨리 사라지지 않도록
감쇠를 줄였다. 측정점 주변 한 셀은 해당 스캔의 free ray에서 제외한다.
장애물 endpoint 자체를 부풀리지 않으며, 충분히 반복된 빈 공간 관측은
기존 물체를 지울 수 있다. 이 보수적인 inverse model은 새로 생성하는
기록 지도에 적용하며, 기존 live mapper의 기본 모델은 별도다.

정수 ray 계산 중복과 tile 정렬·범위 계산을 줄였다. 기본 raster 셀 결과,
tile checkpoint 복구와 직렬/병렬 처리 순서는 회귀 테스트로 확인한다.
전체 LiDAR 관측과 측정점은 보존한다. 화면에서 멀리 있는 점을 숨기는
방식으로 정확도가 개선됐다고 판단하지 않는다.

최신 처리는 **새 지도 만들기 → 재생**으로 선택한다. 이전 파생 지도
pointer/epoch는 복구할 수 있게 보존하고 원본 bag·영상·센서·PWM 기록은
변경하지 않는다. 기존 지도는 생성 당시 알고리즘 fingerprint로 유지된다.

독립 측량 좌표가 없으므로 기록 간 정합 지표는 상대 일관성 비교다.
원거리 장기 정합과 장착 기울기·gyro bias·beam timing 및 전역 drift는
아직 완료로 판단하지 않는다. 2D LiDAR의 beam 배열이 실제 수집 시각
순서인지 확인하기 전에 time_increment만으로 임의 deskew를 적용하지
않는다. 실제 모터 명령과 자율주행 출력은 계속 보류한다.

Jetson CPU 4개 제한의 격리된 전체 처리 시험은 다음과 같다. 다른 부하와
네트워크에서는 결과가 달라질 수 있다. 세 기록 모두 지도 좌표계 1개,
중간 reset 0회, backlog 정지·재개·오래된 Play 차단·뒤로 seek 검증을
통과했으며 원시 source hash를 보존했다.

| 기록 | 기록 길이 | 이전 전체 처리 | 수정 후 전체 처리 |
| --- | ---: | ---: | ---: |
| 20261003T080909Z_both | 210.12초 | 223.07초 | 185.31초 |
| 20261003T080351Z_both | 246.76초 | 291.96초 | 235.90초 |
| 20261003T072530Z_both | 524.78초 | 629.15초 | 453.59초 |

ARM 회귀 테스트 42개를 통과한 runtime source `33b7833`을 SSH로 적용했다.
다른 12개 역할·원본 파일 59개·보호된 설정·저장된 live 지도는 보존됐다.
실제 모터를 구동하지 않았다. 정합 잔차 비교는 대체로 개선됐지만 일부
장기 원거리 지표는 악화됐다. 072530 저회전 20초 구간 7개에서 raw gyro와
추정 방향의 차이 중앙값은 이전 0.971°에서 1.050°로 약간 증가했다.
따라서 회전 정확도 전체를 해결했다고 판단하지 않는다. gyro 자체도
독립 측량 기준이 아니다.

실제 브라우저에서는 미처리 117초가 남은 상태에서 Pause 뒤 약 99초간
기록 지도 반복 조회가 없었고, 과거 시각 이동 뒤 수동 확대를 유지했다.
HTTP 512kbps/250ms 시험 약 147초 동안의 화면 지도 지연 p50/p95/max는
2.94/7.80/8.95초였다. 이 조건의 종단간 실시간 성능은 아직 미완료다.
WebSocket까지 동일하게 제한됐다는 증거는 아니다.

7개 원시 기록의 짧은 2초 간격 겹침 거리 중앙값은 모두 소폭 개선됐다.
동적 가지·가림·보이지 않는 영역 때문에 최근접점 거리 자체를 위치 오차로
해석하지 않는다. 집계는 `map_speed_accuracy_20261005.json`에 보존한다.
원시 위치·궤적·영상·브라우저 캡처는 public repository에 넣지 않는다.

지연이 큰 072530 145–205초 구간 계측에서는 600스캔에 정합 3,635회를
시도했다. 추가 private 실험은 모두 종료됐으며 실제 runtime은
`33b7833`으로 유지했다.

- coverage 0.7 후보는 7개 기록을 완료했다. 일부 점 겹침이 더 좋아졌지만
  저회전 구간의 gyro와 방향 차이는 1.050° → 1.445°로 증가했다. 독립
  측량 기준이 없으므로 전반적으로 더 정확한 기본값으로 채택하지 않았다.
- 마지막 관측 위치·속도와 최신 gyro 증분을 첫 탐색 seed로 쓰는 후보는
  3개 기록을 완료했다. 개선이 작거나 혼재됐고, 20초 계측 prefix의
  정합 호출은 943 → 1,179회로 증가했다. 호스트 부하 차이로 wall time을
  직접 속도 개선으로 해석하지 않았다. 이 후보도 배포하지 않았다.

실제 드라이버의 `inverted=false`, `angle_compensate=true`를 읽기 전용
ROS parameter 조회로 확인했다. 설치된 고정 버전은 빔을 각도순으로
정렬하고 node를 여러 각도 bin에 복제한 뒤 배열을 반전한다. 그 배열의
`time_increment`만으로 개별 측정의 실제 수집 시각을 단정할 수 없다.
원본의 반복 range/quality가 모두 가짜 측정이라는 뜻도 아니다.
근거는 [SLAMTEC 고정 버전의 driver source](https://github.com/Slamtec/sllidar_ros2/blob/34300099fadfc772965962dec837bf436706188f/src/sllidar_node.cpp)다.
드라이버·장착·센서 설정을 변경하지 않았다.

다음 정확도 작업은 SDK 수집 순서·동기 flag·host timestamp 지연 확인,
향후 native 측정 metadata 보존, 관측 가능한 gyro bias, 지속적인 local
geometry 및 전역 drift 검증이다. 정지 강제나 반복된 원시 포인트 삭제로
더 좋은 수치가 나오게 만들지 않는다. live/SIM의 adapter 이식과 느린
회선 pacing도 미완료로 유지한다.

검증·실제 배포·7개 원시 기록 비교 결과와 다음 재개 위치는
UBTS `todo.md` 및 private `speed-accuracy-checkpoint.json`에 갱신한다.
브라우저 측정은 실제 HTTP 연결 조건에 의존하며 모든 네트워크에서
종단간 실시간 성능이 보장된다는 의미는 아니다.
