# ESP8266 로버 제어

`rover_control_test`의 `UBTS_WHEEL_PWM_V2`와 WheelController를 사용한다. 기존 WAVE ROVER UART/HTTP 프록시와 파일 명령 경로는 폐기했다.

## 연결 구조

브라우저 → Dashboard 자동 세션 → `/run/ubts-rover/control.sock` → `ros2-esp-rover-bridge` → 고정 USB ESP → 모터.

ESP 브리지만 모터 포트를 연다. LiDAR와 ESP는 같은 USB VID/PID를 사용하므로 장치 이름이나 CP210 자동 탐색으로 구분하지 않는다. Compose가 서로 다른 by-id 장치를 매핑하고 ESP는 실제 udev ID_SERIAL도 확인한다. flock과 TIOCEXCL로 중복 소유를 차단한다. 기존 Tk 테스트 프로그램을 쓸 때는 ESP 브리지를 먼저 중지하고, 테스트 프로그램을 완전히 종료한 후 다시 시작한다.

ROS에는 `/rover/status`, `/rover/control/requested`, `/rover/control/applied`를 발행한다. `/cmd_vel`은 구독하지 않는다. 수동 조종 종료 후 자동 주행으로 넘어가지 않는다. `applied`는 MCU의 PWM 피드백이며 엔코더 속도가 아니다.

왼쪽 방향 D8/D5, 오른쪽 방향 D3/D0, 전원 D1/D2/D6/D7 매핑을 유지한다. 정상 입력 해제는 MCU 가감속, STOP/Esc/창 이탈/통신 만료는 즉시 정지를 요청한다. MCU의 전원 핀 유지 정책도 기존 펌웨어와 같다. 웹 STOP은 물리 전원 차단 장치가 아니다.

## 사용

1. `/rover-control`에서 **조종 활성화 OFF**를 눌러 ON으로 바꾼다. 별도 조종 암호는 없다. 다시 누르면 정지하며 OFF가 된다.
2. WASD 또는 방향 버튼을 누르는 동안 이동한다. 한글 입력 모드에서도 물리 WASD 키를 사용한다.
3. W+A / W+D / S+A / S+D는 이동하면서 좌·우로 꺾는다. 안쪽 바퀴는 설정 속도를 유지하고 바깥쪽은 1.5배, 최대 100%다. 속도 100%에서는 바깥쪽을 더 높일 수 없어 대각선도 직진한다.
4. 슬라이더는 주행 중에도 바로 반영된다. Q는 −5, E는 +5 퍼센트 포인트이며 한 번 누를 때 한 단계만 바뀐다. 길게 눌러 자동 반복하지 않는다. 조종 패널을 숨기거나 속도 슬라이더에 포커스가 있어도 WASD/Q/E는 작동한다.
5. STOP/Esc 또는 창 이탈 시 조종권이 해제된다. 재접속으로 자동 활성화되지 않는다.

속도 30%의 좌/우 요청: W=30/30, A=−30/30, S=−30/−30, D=30/−30, WA=30/45, WD=45/30, SA=−30/−45, SD=−45/−30. 후진 A/D는 후진 경로가 좌/우로 휘는 방향이다. W→WA→W 및 속도 변경 시 별도 정지 명령을 끼워 넣지 않으며 V2 MCU의 기존 가감속을 따른다. 응답 대기 중 입력 변경은 최신 상태만 유지하고 응답 직후 전송한다.

대시보드를 연 브라우저에 세션을 자동 생성하며 별도 입력은 필요 없다. 조종권은 한 세션만 소유한다. 연속 입력에는 일회용 티켓과 순번을 적용한다. 입력 0.75초 만료, 티켓 1.5초 만료, 유휴 조종권 30초 만료다. keepalive는 이동 유효 시간을 늘리지 않는다. MCU watchdog 2초가 호스트 정지에 대비한다. 너무 느린 망에서는 정지 후 재활성화가 필요하며 안전 시간을 늘리지 않는다.

## 저속 전송

전송 품질의 자동 모드는 작은 프레임부터 시작해 수신 확인 시간에 따라 조절한다. 카메라와 LiDAR는 각 연결에서 하나의 미확인 프레임만 허용한다. 응답이 없으면 연결을 닫고 오래된 프레임을 쌓지 않는다.

| 모드 | 카메라 최대 크기/FPS/JPEG 품질 | 카메라 목표 상한 | LiDAR 표시 |
|---|---|---|---|
| 극저속 (64 kbps) | 160×90 / 2 / 30 | 3 KB/s | 최대 60점, 1 Hz |
| 매우 느린 망 | 320×180 / 4 / 40 | 30 KB/s | 최대 180점, 3 Hz |
| 균형 | 640×360 / 10 / 55 | 120 KB/s | 최대 450점, 5 Hz |
| 고화질 | 1280×720 / 15 / 70 | 400 KB/s | 원본 설정 이내, 10 Hz |

종횡비를 유지하고 작은 입력은 확대하지 않는다. 예산은 애플리케이션 메시지 기준이며 TCP/TLS·상태 정보·IMU 트래픽은 별도다. 실제 회선이 느리면 수신 확인이 FPS를 더 낮춘다. 느린 모드에서는 라이브 AI 오버레이를 생략한다. ROS 원본, AI 입력, 녹화 원본에는 이 축소를 적용하지 않는다. LiDAR는 극좌표 배열로 전송하고 브라우저에서 표시 좌표를 복원한다.

자동 모드는 극저속에서 시작한다. 극저속에서는 IMU 표시 1 Hz, 전체 텔레메트리 조회 10초 간격을 적용해 영상 외 트래픽도 줄인다. 선택한 프로필은 화면 미리보기에만 적용된다. 64 kbps는 목표 회선 예산이며 가용 대역폭이나 지연 보장은 아니다.

## AP와 설치

관리 AP는 `band=bg`, 채널 6, 절전 비활성화로 유지한다. 현재 인터넷에 연결한 station의 5GHz 사용과 AP의 2.4GHz 설정은 별개다. 프로필 검증은 기존 프로필의 대역도 확인하며 활성 AP를 원격으로 강제 변경하지 않는다. 2.4GHz 자체가 특정 거리를 보장하지 않으며 안테나·장애물·간섭에 따른 현장 시험이 필요하다.

배포 전 코드와 Compose, 이미지 ID를 백업한다. 레거시 `unist-orachard-ros2-rover-bridge`는 restart=no로 바꾸고 중지한 뒤 새 브리지를 실행한다. ESP는 disarmed 상태로 시작하고 V2 펌웨어를 확인하기 전 조종을 허용하지 않는다. 잘못된 장치 또는 장치 분리 후에는 고장 상태를 유지한다. 장치를 확인하고 컨테이너를 다시 생성해야 한다. USB 재연결로 장치 번호가 달라져도 다른 USB 장치를 자동 선택하지 않는다.

단위 테스트는 가짜 모터 및 로컬 WebSocket에서 수행한다. 정지 상태 실장비 확인과 실제 주행·거리 시험은 별도로 기록한다.
