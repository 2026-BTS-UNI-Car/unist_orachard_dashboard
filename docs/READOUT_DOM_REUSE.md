# 센서 수치 표시 노드 재사용

현재 소스 기준선 `fded009`에서 `static/app.js`의 `renderReadout` 함수 하나만 변경했다. IMU와 LiDAR 수치가 바뀔 때 기존 행과 텍스트 노드를 재사용한다. 행의 개수·순서·라벨·값·색상은 매번 반영하며, 외부에서 하위 DOM이 교체되면 캐시를 무효화한다. 텍스트는 기존 HTML escape와 같은 리터럴 문자열로 표시한다.

앱의 원시 CRLF 바이트를 유지했고, 변경 함수를 원 함수로 역치환하면 기준선 앱 전체의 SHA256이 정확히 일치한다. `C0_SOURCE_SHA256.json`의 92개 파일 중 앱의 해시와 크기 한 행만 갱신했다. 상세 값과 역치환용 함수는 `READOUT_DOM_REUSE_SOURCE.json`에 있다. 이 manifest는 배포 이미지 전체를 재현하거나 설치 상태를 증명하는 자료가 아니다.

검증은 기존 Node VM 방식의 `node tests/test_readout_dom.mjs`로 수행한다. 실제 IMU·LiDAR 표시와 같은 행을 900회 갱신하여 원 함수와 출력 의미를 비교하고, 행 증감·빈 행·외부 DOM 교체·안전한 텍스트·색상 변화를 확인한다. 이 시험은 실제 브라우저 레이아웃이나 FPS를 측정하지 않는다.

카메라 JPEG·해상도·화질·ACK·센서 구독·지도 갱신·사용자 입력·Stop 경로는 바꾸지 않았다. 이미지 decode promise나 화면 밖 지도 렌더링 생략은 포함하지 않는다. Git 게시와 Jetson 설치는 별도 단계이며, 실제 성능 개선은 아직 확인하지 않았다.

새 Windows worktree에서 Git의 자동 줄바꿈 변환이 해시 검증 대상 문서·fixture 7개의 LF를 바꾸는 문제도 확인했다. 해당 7개 정확 경로에만 `text eol=lf`를 지정했다. 파일 본문과 92개 소스 해시는 그대로이며, CRLF 원본 앱의 기존 `-text` 규칙도 유지한다. 전역 Git 설정이나 다른 파일의 형식은 변경하지 않는다.
