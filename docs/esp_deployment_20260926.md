# ESP 로버 전환 검증 — 2026-09-26

## 조사 결과와 변경

- 기존 대시보드는 WAVE ROVER UART와 파일 TTL 명령, `/cmd_vel` 복귀 경로를 사용했다. 이를 제거하고 `rover_control_test`의 V2 WheelController를 별도 ESP USB 소유 서비스로 옮겼다.
- LiDAR와 ESP는 VID/PID가 동일한 Silicon Labs 장치다. 기존 LiDAR 자동 탐색이 ESP를 선택할 수 있어 드라이버가 중지돼 있었다. 서로 다른 by-id 장치를 Compose에서 각각 고정하고 ESP는 udev ID_SERIAL을 재확인한다.
- 대시보드 조종은 서버 세션에 묶인 단일 조종권, 일회용 입력 티켓과 순번을 사용한다. 후속 요청에 따라 별도 조종 암호를 제거했다. 정지 후 과거 명령이나 재연결이 조종을 자동 재개하지 않는다.
- 압축 ROS 카메라 입력에도 실제 미리보기 축소를 적용했다. 카메라·LiDAR·IMU 전송은 수신 확인과 최신 값만 사용하는 방식으로 바꿨다. ROS/AI/기록 원본은 유지한다.
- 느린 모드에서 전체 상태 조회와 IMU 표시 빈도도 줄인다. 과거 기록·지도는 사용자가 기록을 선택한 후 다운로드한다.

## 실장비 확인

Cloudflare SSH로 Jetson에 접속했다. 신규 `ros2-esp-rover-bridge`는 `UBTS_WHEEL_PWM_V2`를 확인했고, 브라우저 인증 API의 조종 활성화 → 좌우 PWM 0 → STOP 경로가 성공했다. 네 방향 핀 D8/D5/D3/D0의 MCU 피드백은 모두 0이다. 전원 D1/D2/D6/D7은 기존 펌웨어 정책에 따라 255를 유지한다.

**비영점 바퀴 명령과 펌웨어 쓰기는 실행하지 않았다.** 주행 방향, 접지 상태의 제동 거리, 전원 차단, 실외 도달 거리는 검증되지 않았다.

카메라 원본 1280×720·15fps, LiDAR 약 3,150점/스캔, IMU `/imu/data_raw` 수신을 확인했다. 자세 영점 보정은 실행하지 않았다. 외부 HTTPS 대시보드에서 센서 연결과 ESP disarmed 상태를 확인했다.

동일한 실행 중 센서에서 프로필별 6개 메시지를 수집했다. 극저속 측정은 수신 확인 전에 `메시지 바이트 / 8000 + 150ms` 지연을 추가했다. 이는 로컬 WebSocket 수신 지연 모사이며 무선 거리 시험이나 실제 회선 대역폭 제한 시험은 아니다.
