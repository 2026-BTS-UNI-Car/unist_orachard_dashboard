2. 동작 (상태기계)
-----------------
  start(t, TurnRequest, motor_output=False|True, observe=False) → PRECHECK → CREEP_OUT → PIVOT_1 → TRAVERSE →
  PIVOT_2 → SETTLE_ACQUIRE → DONE. 어느 상태에서든 이상이 생기면 ENDED(종결, 출력 0/0).
  tick(now, hold_active)는 core.Decision(left, right, state=단계, reason, terminal, summary)을 돌려준다(부호 있는 duty).
  - PRECHECK(출력 없음): 정지 ≥ 2 s, 진동 ≤ 0.3, IMU 간격 중앙값 ≤ 0.04 s, 입력 신선. 이 정지 구간에서 자이로
    바이어스를 고정한다(|b0| ≤ 0.3 °/s, 표준오차 ≤ 0.1 °/s). 열 축은 이 run 추정기의 통로 띠 → 열 run 힌트
    (heading_error) → 운용자 "현재 heading = 열 방향" 확인 순으로 정한다. 회전 프레임(원점 = 차체 중심,
    +x = 열 축(headland 쪽), +y = 왼쪽)을 고정한다. 다음 통로 표가 ABSENT면 거부한다(운용자 무시 가능).
  - CREEP_OUT(전진만): 열 축 heading 유지(|L−R| ≤ 10). 회전 쪽 줄기선 띠의 끝 + x_c를 지나고, pivot 원판
    1.28 m가 3 scan 연속 비고, 앞 여유가 표의 reach를 덮으면 멈춘다.
  - PIVOT_1/2: (−s·d, +s·d). d = 시작 duty → 회전이 없으면 1 s마다 +10 → cap. cap에서도 회전이 없으면 pivot_stall.
    회전 중에는 그 duty를 유지하고, 남은 각 ≤ 회전율 × coast 시간이면 놓는다. 정지 후 판정해서 ±8°면 통과,
    모자라면 같은 방향으로 1회 보충, 넘침 ≤ 20°는 다음 단계의 절대 목표가 흡수, 그 밖은 종결. 반대 방향 pivot은 없다.
  - TRAVERSE(전진만): heading s·90°를 유지하며 다음 통로 중심(−lateral0 + s·W − 예측 PIVOT_2 이동)까지 간다.
  - SETTLE_ACQUIRE(출력 없음): 새 추정기로 정지 상태에서 다음 통로를 잡는다. READY면 DONE. 열 추종은 자동으로 시작하지 않는다.
  - hold-to-run: 단계마다 단계 경계 뒤의 "새 누름"이 필요하다. 놓으면 바로 0/0(PAUSED). 단계당 일시정지 최대 3회.
    pivot을 재개하면 시작 duty부터 다시 오른다. 전진 단계는 같은 절대 목표로 이어 간다.
  - 출력 모드: motor_output=True는 turn_assist_enabled, motor_output_enabled, turn_feasibility()['output_allowed']
    (C6 시작/cap, pivot_surface_ok, C2 breakaway, C3 속도, 회전 전진 duty 규칙)가 모두 맞을 때만 시작된다.
    motor_output=False(기본)는 같은 상태기계를 돌리되 Decision은 항상 0/0이고 summary['proposed']에 제안 값을 남긴다.
    observe=True(T1 shadow)는 PRECHECK 뒤 사람이 손으로 회전하는 동안 줄기선 끝, 원판, 앞 여유, 회전마다
    자이로 대 scan matching 차이, 다음 통로 획득을 기록만 한다. 출력은 절대 없다.
    TurnRequest.pivot_only=True(T2)는 PRECHECK → PIVOT_1 → DONE 'pivot_done'이다(creep·횡이동 없음, pivot 전에는
    원판 여유만 본다). 열 축 띠가 없는 넓은 곳에서는 operator_aligned=True로 쓴다.

  종결 사유(전부 0/0, terminal=True; 호출자는 정지 확인 또는 terminal_stop_wait_s 뒤 op stop):
    turn_guard_violation:*, pivot_stall, pivot_too_slow, pivot_stall_budget, pivot_wrong_direction, pivot_rate_excess,
    pivot_overshoot, pivot_undershoot, pivot_clearance_lost, pivot_start_clearance, pivot_front_insufficient,
    yaw_disagreement, imu_gap_in_pivot, turn_timeout, settle_timeout, creep_backstop, creep_front_blocked,
    creep_headland_limit(검토 추가, 11절), creep_side_blocked, creep_side_drift, traverse_backstop,
    traverse_front_blocked, traverse_side_blocked,
    odometry_invalid, uncommanded_motion, stale_repeat_limit, stall_guard_repeat_limit, pause_limit,
    precheck_timeout:*, next_corridor_absent, row_width_mismatch, clock_regression, internal_error:*, operator_stop
  정상 끝(DONE): pivot_done(pivot_only), turn_done_ready(정지 획득), turn_done_ready_odometry(획득 실패, 회전 프레임 추측 항법으로 인계
    범위 안. 화면에 그렇게 표시), turn_done_not_ready, observe_done.


3. 설계에서 바꾼 점 (근거는 SIM과 실기록 재생; 7·8절)
----------------------------------------------------
  (1) 앞 여유 기준: 설계식 front ≥ reach − x_c + 0.3은 front_clearance가 차체 앞면부터 재는 값이라 0.61 m
      이중 계산이었다. reach − x_c + 0.3 − L/2(+ 정지거리)로 고쳤다.
  (2) 줄기선 끝은 회전 쪽 띠만 쓴다. 반대쪽 줄기선·수관은 pivot 원판(1.28 m, 모든 방향) 조건이 막는다.
      설계처럼 두 띠의 최댓값을 쓰면 반대쪽 수관 때문에 약 0.7 m 더 나간 경우가 SIM에서 나왔다.
  (3) 줄기선 끝은 PRECHECK 위치(x = 0)에서 시작해 4 m 이하 간격으로 이어지는 마지막 반환이다. 처음 구현
      (차량 옆 반환에서 시작)은 차량 옆 나무 1그루가 빠지면 줄기선 끝을 차량 뒤로 잘못 잡았다. SIM에서 줄기선 끝
      1.9 m 앞에서 PIVOT_1을 시작했고, 회전 중 원판 여유 검사(pivot_clearance_lost)가 멈췄다.
      띠 안 수관 반환도 끝에 포함된다. 그래서 정지 위치가 수관이 열 방향으로 뻗은 만큼 더 나간다(보수적).
  (4) 정체 하중 시간은 |자이로| < 1.5 °/s(= stall_min_deg / window)일 때만 센다. 5 °/s 미만을 모두 세면 느리게
      도는 pivot도 정체로 셌다. 기본 한도 4 → 4.5 s(60 → 80 사다리가 3.8 s). cap에서 돌기는 하지만 확인 속도
      (5 °/s) 미만이면 'pivot_too_slow'로 따로 끝낸다.
  (5) 판정 heading: 설계는 LiDAR와 자이로 차가 5°를 넘으면 자이로를 썼다. SIM에서 자이로 척도 오차(5.8 %)가
      PIVOT_1에서 남아 PIVOT_2에서 10°를 넘었다(실기록 척도 오차도 p90 +6~7 %). 지금은 정지 판정 때 차가 10° 이하면
      항상 scan matching heading을 쓰고 자이로를 거기에 맞춘다. 회전마다 자이로 이득을 0.92–1.08로 학습한다.
      놓는 시점과 heading 유지는 "가장 최근의 유효한 scan matching heading + 그 뒤 자이로 증분"으로 계산한다.
      자이로 대 LiDAR 10° 초과 종결은 그대로 둔다.
  (6) pivot 중 IMU 간격 종결 0.15 → 0.4 s. 10/10 기록의 pivot 구간 595개 중 7개에서 수신 간격 0.157–0.365 s가
      있었다(0.15 s였다면 1.2 %가 거짓 종결). 0.3 s를 넘으면 먼저 stale_imu로 일시정지한다(imu_max_age_s).
  (7) 바이어스 기준: 표본 표준편차 ≤ 0.3이 SIM 정지 잡음(최대 0.46 °/s)에서 계속 실패했다. 표본 표준편차 ≤ 1.0
      (움직임 검출) + 평균의 표준오차 ≤ 0.1 °/s로 바꿨다.
  (8) 횡이동 목표에 PRECHECK의 통로 내 측면 위치(lateral0)를 넣었다(빠뜨리면 그만큼 옆 통로 중심에서 벗어남).
  (9) 폭 불일치: 통로 띠 폭은 수관 때문에 좁게 나온다. |띠 폭 − W| > 1.2 m만 종결하고 그 밖은 경고한다.
      인계 폭 조건은 W + 0.5 / W − 1.0까지 허용한다.
  (10) PIVOT_2 넘침 ≤ 20°도 종결하지 않고 SETTLE에서 READY/NOT_READY로 판정한다(정지 상태라 안전).
  (11) SETTLE 정지 획득은 열 끝에서 2–3 m 밖이라 자주 실패한다. 정지 획득이 통로를 한 번도 못 봤고,
       PRECHECK 띠가 W를 확인했으면 회전 프레임 추측 항법으로 인계 판정을 한다(turn_done_ready_odometry).
       통로를 봤는데 조건을 못 맞추면 그 측정이 이긴다(NOT_READY).
  (12) 회전 측정값(C6 등)이 없어도 설정 파일은 유효하다. 열 실행기를 막지 않도록 turn_feasibility는 설정 오류가
       아니라 start(motor_output=True)에서 거부한다.
  (13) 전진 ↔ pivot 형상 전환: 새 누름이 들어와도 직전 형상의 MCU fade(|d|/100 + 0.32 s)가 끝날 때까지 'waiting_fade'로
       기다렸다 시작한다(TurnGuard 위반으로 끝나던 문제, SIM에서 발견).


4. TurnGuard (회전 run 전용, guard.py)
------------------------------------
  - (0,0)은 항상 허용. pivot은 정확히 (−s·d, +s·d), 시작 duty ≤ d ≤ cap ≤ 100, 크기가 같아야 한다. s는 시작 때 고정.
  - 전진은 두 값 모두 [breakaway + inner_margin, 회전 전진 duty + turn_drive_diff_cap_pct(≤ duty_cap_pct)], |L−R| ≤ 10.
  - 단계 묶음: pivot 단계는 pivot이나 0만, 전진 단계는 전진이나 0만, 그 밖은 0만.
  - 형상 전환: 0/0을 |d_last|/100 + 0.32 s 이상 보냈고 정지 ≥ 0.4 s일 때만. 반전 경로(fade → 120 ms → ramp)를 쓰지 않는다.
  - 연속 pivot 안에서 duty는 유지하거나 1 s 이상 간격으로 +10 이하만 올린다. 내림은 위반.
  - 예산: 회전 1회 pivot 명령 30 s, pivot 단계당 정체 하중 4.5 s. TurnAssist는 0.3 s 먼저 스스로 끝낸다.
  - 위반이면 0/0 + 'turn_guard_violation:<이름>'(버그로 취급). SignedBridgeClient.drive_signed가 같은 형상 검사를 한 번 더 한다.


5. 실행기 연결 방법 (executor_main / operator_http 쪽, 아직 안 함)
------------------------------------------------------------
  - TurnAssist(cfg)를 Runner 옆에 하나 만든다. 같은 센서 콜백에서 같은 수신 시각으로 feed_scan/feed_imu를 둘 다
    부르거나, 활성 run 쪽만 부른다(회전 run은 시작 때 새 추정기를 만든다). Runner와 TurnAssist는 동시에 열지 않는다.
  - 운용자 화면: 방향(left/right), W(줄자), x_c·reach(인쇄 표의 수관 등급), headland 깊이(줄자), creep 최대,
    "현재 heading = 열 방향" 확인, 다음 통로 ABSENT 무시. 열 run이 끝난 뒤 차가 안 움직였으면 그 run의 마지막
    heading_error_deg를 row_heading_error_deg 힌트로 넘긴다.
  - 출력: CLI 모터 플래그 + Arm + 설정이 모두 맞을 때만 start(motor_output=True). 회전 run에서만
    SignedBridgeClient(allow_signed=True)를 쓰고, drive_signed(d.left, d.right, assist.guard.shape_problem)로 보낸다.
    열 run은 지금처럼 BridgeClient.drive(전진 전용). 전송 규칙은 열 run과 같다(10 Hz + 0으로 바뀌는 즉시 전송, deadman:true).
  - tick 20 Hz. 루프 정체 감시 → assist.pause(t, 'stall_guard'). STOP·브리지 latch → assist.abort(t, ...).
  - terminal이면 0/0을 정지 확인 또는 terminal_stop_wait_s까지 보내고 op stop. DONE이면 summary['handoff']
    (ready, source, heading_error_deg, lateral_offset_m, odometry_*)를 보여 주고 운용자가 열 추종 Start를 누른다.
  - 기록: 매 tick Decision.summary, 끝날 때 status()(pivots, events, warnings, guard, handoff, observe_log).
  - 현장 C6 값: turn_onsite_update(file_cfg, current_cfg, params)로만 바꾼다. 시작/cap duty(cap은 파일 값 이하),
    pivot_surface_ok, coast, ICR, 회전 전진 duty(파일 값 이하). turn_assist_enabled / motor_output_enabled는 바꿀 수 없다.
    field_calib/recommend.py의 turn_candidates가 C6 기록에서 이 키들의 후보를 만든다(pivot_surface_ok는 사람이 확인).
    [통합 2026-10-22] 후보는 회전 보조가 켜진 설정(turn_assist_enabled)에만 설정에 쓰고, 꺼져 있으면(이번 주말) 보고서 후보로만
    남는다(손대지 않은 회전 블록 = digest 불변). ICR 규약은 하나다: base 좌표(앞 +, 왼쪽 +), left = 반시계 pivot,
    config.icr_base_from_lidar = field_calib의 LiDAR 기준 값 + lidar_x_in_base_m (README_FIELD 12.6, 시험 IcrConventionTest).

9. 남은 문제
-----------
  1. executor_main / operator_http 연결이 아직 없다(다른 작업 트리). 회전 패널(입력·단계 표시·새 누름·handoff 표시),
     회전 run에서만 SignedBridgeClient(allow_signed=True), 기록, turn_onsite_update 연결이 필요하다(5절).
     실제 브리지 + ESP 펌웨어로 음수 duty를 보낸 시험은 없다(in-process RoverControl까지만 확인).
  2. 회전 출력에는 그 headland 노면의 C6(6/6 회전, pivot_surface_ok)이 있어야 한다. 저 duty(55–80 %) 정지 출발 pivot
     실측은 1건뿐이다. 시작/cap 기본 60/80은 가정이다.
  3. 필요한 headland 깊이: 줄기선 끝 판정이 띠 안 수관 반환을 포함해서, 표의 "reach + 0.3"보다 수관이 열 방향으로 뻗은 만큼
     더 필요하다. SIM에서 4 m 울타리는 항상 멈췄고(안전), 5 m는 됐다. 첫 시도는 5 m 이상에서 한다.
  4. 인계 측면 오차: PIVOT_2 회전 중심이 흩어져(SIM sd 0.25 m, 실측 p90 0.32–0.41 m) 다음 통로 중심에서 0.4–0.6 m
     벗어나는 경우가 25–35 %(SIM) → NOT_READY. SIM 열 추종은 이 위치에서도 23/23 들어갔다. handoff_lateral_max_m을
     0.6으로 올리는 것은 T1/T3 실측 뒤에 결정한다. C6 ICR 보정은 계통 성분(왼쪽 pivot 약 0.2 m)만 줄인다.
  5. 정지 획득(SETTLE)은 열 끝 2–3 m 밖이라 SIM에서도 통로 띠가 치우쳐 나온다. 추측 항법 대안(turn_done_ready_odometry)은
     통로를 한 번도 못 봤을 때만 쓴다.
  6. yaw 불일치 종결 10°: 실기록 최대 8.2°라 여유가 작다. 느리고 긴 pivot일수록 자이로 오차가 쌓인다. 제어는 LiDAR heading을
     쓰므로 이 종결은 교차 확인이다. 현장 T1에서 분포를 다시 본다.
  7. 횡이동 중 LiDAR가 0.45 s 넘게 끊기면 일시정지하지만 그 사이 이동이 오도메트리에서 빠질 수 있다(경고 odometry_gap_*,
     결과는 NOT_READY). 종결로 바꿀지 현장에서 정한다.
  8. 정체는 무조건 종결이다(재시도 없음). 전류를 기록하지 않아 토크 부족과 드라이버 보호를 구분할 수 없다.
  9. MCU 상태가 2 Hz라 적용 duty를 바로 확인할 수 없다. 회전 판단은 IMU·LiDAR 반응만 본다.
  10. PRECHECK는 열 끝의 통로 띠(없으면 열 run 힌트나 운용자 확인)가 필요하다. 마지막 열 판단은 하지 않는다(사람).
  11. 시험 범위: Windows Python 3.13(전체) + WSL Ubuntu 22.04 Python 3.10.12 / numpy 1.21.5 / scipy 1.8.0(회전 시험 92개).
      Jetson(ARM)에서 돌린 적은 없다.
